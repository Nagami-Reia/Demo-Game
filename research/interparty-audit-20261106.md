# 党际关系现状审计（2026-11-06）

本次为代码审计，没有将政治立场当作现实法律禁令，也没有启动新的党籍招募硬禁。

## 当前确实在运行的内容

- 同党、CDU/CSU共同党团、执政伙伴、跨执政/在野、不同反对党五类关系进入行动和电脑估价。
- 相同党三人出战有组织加成；另一党三人后续有组织加成，开局仍需跨党谈判。
- 各党政策位置影响相容性与政策目标分，数据中部分具体党际关系还有合作参数。
- CDU/CSU/SPD实际出战AfD人物，每人触发0.8原始民调冲击，上限2.4；只收藏不出战不触发。
- 招募保留原党籍，不表示现实人物加入了玩家政党。

## 已确认的缺口

1. **没有按党籍禁止招募。** 普通池只限制招募中心等级、是否已拥有和中立主席团。特选按阵营优先选卡，但双方仍可竞价。最终成交和部署也没有党际资格检查。
2. **具体关系只有8/15对。** 缺少：CDU / Linke、CSU / Grüne、CSU / Linke、CSU / AfD、SPD / AfD、Grüne / AfD、Linke / AfD。未定义关系会使用默认合作值，不能把“没有资料”当成确定的友善关系。
3. **反对党之间的差异太弱。** AfD与Grüne/Linke均落入oppositionPeer，匹配议题的监督还可能获得+0.1；共同在野不应自动形成政治协作。
4. **防火墙只检查执政玩家。** Grüne或Linke电脑使用AfD卡目前没有对应舆论代价。
5. **高谈判、已有信任及专家修正可覆盖不少跨党成本。** 成功协商可以改善议题合作，但现规则未设置不能被一般社交加成抹去的政治红线。
6. **买下对方领袖会产生组织否认效果。** 完全封掉所有跨党招募会删除用户原先明确要求的“抢领袖卡”策略，需先明确哪些情况属于谈判对象、哪些属于正式合作。

## 建议的分层规则（尚未实施）

|关系|招募/抢卡|出战合作|
|---|---|---|
|本党|正常|完整同党协同|
|CDU/CSU|正常|共同党团协同，保留党籍|
|Union与SPD|正常|伙伴协作，但保留议题分歧|
|其他有议题合作空间的组合|可以谈判招募|根据具体议题、人物和信任限制|
|AfD与其他党|应单列政治红线，不能走一般oppositionPeer|设定明确禁用或高成本例外；红线不能被同州/工作组/高谈判自动消除|

如果采用硬禁，最重要的是把检查统一放到资格函数中：双方出价、自动成交、特选、部署和电脑决策都调用，按钮显示只负责提示，不能只把玩家按钮变灰。共享卡池若仅一方有资格，应避免该方无竞争低价垄断；双方无资格应流拍。旧存档中已拥有的卡必须有明确兼容规则。

建议先补齐党际矩阵与红线，再决定硬禁名单。对AfD的全面招募封锁与现有“抢维德尔削弱对手”的核心玩法有直接冲突，不能把二者同时声称完全保留。可以选择限制正式出战合作、保留领袖谈判/争夺用途；也可以把它移入特殊谈判事件，但那是一次机制调整。
